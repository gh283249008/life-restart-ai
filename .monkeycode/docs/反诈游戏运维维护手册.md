# 反诈游戏运维维护手册

## 1. 适用范围

- 项目：`好薯坏薯・票务反诈局`
- 部署形态：两台轻量应用服务器（主备）
- 域名切换：阿里云云解析 DNS（GTM 主备容灾）
- 应用架构：
  - 前端静态站点：Nginx 提供 `dist/`
  - 后端代理：`server/index.mjs` 转发 DeepSeek
  - 关键服务：`nginx`、`anti-fraud-proxy`、`anti-fraud-healthcheck.timer`

## 2. 目录与服务约定

- 项目目录：`/opt/anti-fraud`
- 前端静态目录：`/var/www/anti-fraud`
- 后端环境文件：`/opt/anti-fraud/.env.server`
- systemd 服务：`/etc/systemd/system/anti-fraud-proxy.service`
- 巡检脚本：`/opt/anti-fraud/scripts/health_check.sh`
- 巡检定时器：`anti-fraud-healthcheck.timer`

## 3. 关键配置项

`/opt/anti-fraud/.env.server` 示例：

```env
DEEPSEEK_API_KEY=<YOUR_DEEPSEEK_API_KEY>
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
LLM_PROXY_PORT=3001
```

说明：

- `DEEPSEEK_API_KEY` 只保存在服务器，不进入前端代码。
- 前端请求路径固定为 `/api/llm/chat/completions`。

## 4. 日常巡检

### 4.1 服务状态巡检

```bash
# 查看后端代理状态
systemctl status anti-fraud-proxy --no-pager

# 查看定时巡检状态
systemctl status anti-fraud-healthcheck.timer --no-pager

# 查看 Nginx 状态
systemctl status nginx --no-pager
```

### 4.2 本机健康检查

```bash
# 后端探活
curl -s http://127.0.0.1:3001/healthz

# 前端首页响应头
curl -I http://127.0.0.1/
```

## 5. 日志查看

### 5.1 后端代理日志

```bash
# 实时日志
journalctl -u anti-fraud-proxy -f

# 最近 200 行
journalctl -u anti-fraud-proxy -n 200 --no-pager
```

### 5.2 巡检日志

```bash
# 巡检任务日志
journalctl -u anti-fraud-healthcheck.service -n 100 --no-pager

# 巡检输出文件
tail -n 100 /var/log/anti-fraud-health.log
```

### 5.3 Nginx 日志

```bash
# 访问日志
tail -n 100 /var/log/nginx/access.log

# 错误日志
tail -n 100 /var/log/nginx/error.log
```

## 6. 代码更新发布流程

以下步骤在主机和备机都执行。

```bash
# 进入项目目录
cd /opt/anti-fraud

# 拉取最新代码
git fetch --all
git checkout pure-h5-ditto
git pull

# 安装依赖
npm install

# 构建前端
npm run build

# 发布静态文件
mkdir -p /var/www/anti-fraud
cp -r dist/* /var/www/anti-fraud/

# 重启后端代理
systemctl restart anti-fraud-proxy

# 重载 Nginx
systemctl reload nginx
```

发布后验收：

```bash
# 后端探活
curl -s http://127.0.0.1:3001/healthz

# 前端首页
curl -I http://127.0.0.1/
```

## 8. 主备切换与 GTM 验收

### 8.1 GTM 预期策略

- 主地址：主机公网 IP
- 备地址：备机公网 IP
- 调度模式：主备（顺序）
- 健康探测：HTTP / 80 / `/` / `200`

### 8.2 切换演练

在主机执行：

```bash
# 模拟主机故障
systemctl stop nginx
```

在任意终端执行：

```bash
# 查询域名解析
nslookup game.douzhitech.cn
```

预期：解析从主 IP 切换到备 IP。

恢复主机：

```bash
# 恢复主机服务
systemctl start nginx
```

## 9. 自动巡检与日志轮转

已启用：

- `anti-fraud-healthcheck.timer`：每分钟巡检
- `anti-fraud-healthcheck.service`：调用巡检脚本
- `logrotate`：轮转 `/var/log/anti-fraud-proxy.log`、`/var/log/anti-fraud-health.log`、`/var/log/nginx/*.log`

手工验证轮转配置：

```bash
# 预演 logrotate
logrotate -d /etc/logrotate.conf
```

## 10. 常见故障与处理

### 10.1 页面能打开但无法生成对话

排查顺序：

1. `systemctl status anti-fraud-proxy --no-pager`
2. `curl -s http://127.0.0.1:3001/healthz`
3. `journalctl -u anti-fraud-proxy -n 200 --no-pager`
4. 检查 `.env.server` 的 `DEEPSEEK_API_KEY` 是否正确

### 10.2 域名不切换或切换慢

排查顺序：

1. GTM 地址健康状态是否正常
2. 健康探测参数是否为 HTTP/80/`/`/`200`
3. 域名 TTL 是否设置为 `60`
4. 两台机器 `nginx` 是否确实按预期停/启

### 10.3 Nginx 返回 502

排查顺序：

1. `anti-fraud-proxy` 是否运行
2. `curl -s http://127.0.0.1:3001/healthz`
3. `/etc/nginx/sites-available/anti-fraud` 中 `/api/llm/` 反向代理是否指向 `127.0.0.1:3001`

## 11. 安全基线

- 任何情况下都不在前端代码保存真实 API Key。
- 服务器权限最小化，限制 SSH 来源 IP。
- 定期轮换 `DEEPSEEK_API_KEY`。
- 日志中避免输出敏感请求体。
